# Code of conduct

## The short version

Be straightforward and be kind. Assume the other person is trying to help.

## Expected behaviour

- Discuss the change, not the person proposing it.
- Give specific, actionable feedback. "This breaks on Windows because the path
  separator is hardcoded" is useful; "this is wrong" is not.
- Accept that a maintainer may decline a change that is correct but out of scope.
- Respect the project's boundaries: it stays text-only, dependency-free, and
  vendor-neutral, and it never accepts a real document as a test fixture.

## Unacceptable behaviour

- Personal attacks, harassment, or discriminatory language.
- Publishing anyone's private information.
- Posting someone else's confidential documents, credentials, or machine
  details in an issue, pull request, or discussion — including your own by
  accident. If that happens, see below.

## Reporting

Report conduct concerns by opening an issue. If a report itself contains
sensitive information, use the repository's **private vulnerability reporting**
feature instead so it is not publicly visible. See [SECURITY.md](SECURITY.md).

If you accidentally post a private document, credential, or host detail, say so
immediately. Deleting a comment does not remove it from the event history, so
treat any exposed credential as compromised and rotate it.

## Enforcement

Maintainers may edit, hide, or delete contributions that violate this document,
and may block accounts that do so repeatedly. Enforcement is proportionate: a
first, good-faith mistake gets a correction, not a ban.

This document is adapted in spirit from the Contributor Covenant, simplified for
a small project and extended with the data-handling rules this repository
depends on.
